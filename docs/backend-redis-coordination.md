# Redis Coordination

Redis is an ephemeral scaling dependency for v1. PostgreSQL remains
authoritative for accounts, applications, calls, ledger, payments, earnings,
withdrawals, refunds, reports, support, media review, admin audit, provider
callbacks, and outbox events.

## Namespace

Every Redis key is generated by `createRedisKeyRegistry` in
`backend/packages/backend-runtime/src/redis-ephemeral.ts`.

Key format:

```text
<REDIS_KEY_PREFIX>:<CONNECTO_ENV>:<REDIS_SERIALIZATION_VERSION>:<owner>:<safe-parts>
```

Defaults:

| Setting                             | Default    | Purpose                                       |
| ----------------------------------- | ---------- | --------------------------------------------- |
| `REDIS_KEY_PREFIX`                  | `connecto` | Separates Host a Call keys from other apps    |
| `REDIS_SERIALIZATION_VERSION`       | `v1`       | Version marker for stored JSON envelopes      |
| `REDIS_IDEMPOTENCY_TTL_SECONDS`     | `86400`    | Completed/started command replay acceleration |
| `REDIS_HOST_PRESENCE_TTL_SECONDS`   | `45`       | Host heartbeat freshness window               |
| `REDIS_CALL_SIGNALING_TTL_SECONDS`  | `7200`     | RTC signaling room participant metadata       |
| `REDIS_OTP_THROTTLE_WINDOW_SECONDS` | `300`      | OTP request throttle window                   |
| `REDIS_RATE_LIMIT_WINDOW_SECONDS`   | `60`       | HTTP/API throttle window                      |
| `REDIS_CACHE_MAX_STALENESS_SECONDS` | `30`       | Maximum accepted cache age                    |
| `REDIS_LOCK_TTL_SECONDS`            | `15`       | Ephemeral duplicate-work suppression lock     |

Raw phone numbers, idempotency keys, connection IDs, and provider tokens are not
stored in Redis keys. Sensitive key parts are SHA-256 hashed before they enter a
key name.

## Key Inventory

| Owner            | Pattern                                                                          | TTL owner                        | Degraded behavior                               |
| ---------------- | -------------------------------------------------------------------------------- | -------------------------------- | ----------------------------------------------- |
| `idempotency`    | `<prefix>:<env>:v1:idempotency:<route-id>:<idempotency-key-hash>`                | API idempotency adapter          | Use PostgreSQL `idempotency_records`            |
| `otp`            | `<prefix>:<env>:v1:otp:throttle:<subject-hash>`                                  | Identity/OTP module              | Allow durable/provider checks to decide         |
| `presence`       | `<prefix>:<env>:v1:presence:host:<host-id-hash>`                                 | Host presence module             | Fall back to PostgreSQL availability            |
| `call-signaling` | `<prefix>:<env>:v1:call-signaling:room:<call-id-hash>:participant:<participant>` | Calls RTC edge                   | Clients rejoin; call state stays durable        |
| `rate-limit`     | `<prefix>:<env>:v1:rate-limit:<bucket>:<subject-hash>`                           | API edge                         | Fail open for reads; durable checks stay active |
| `cache`          | `<prefix>:<env>:v1:cache:<cache-name>:<cache-key-hash>`                          | Owning read model                | Query PostgreSQL and ignore stale payloads      |
| `lock`           | `<prefix>:<env>:v1:lock:<resource-hash>`                                         | Worker/API duplicate suppression | Continue with PostgreSQL locks/outbox claims    |
| `bullmq`         | `<prefix>:<env>:v1:bullmq:queue:<queue-name>`                                    | Worker queue configuration       | Replay from PostgreSQL transactional outbox     |

## Implemented Uses

- OTP request throttles run before fake/sandbox/live provider dispatch.
- `/v1` HTTP route rate limits use Redis counters and fail open if Redis is
  unavailable.
- Mutating `/v1` idempotency uses Redis only as a short-lived replay
  accelerator; PostgreSQL remains the durable source.
- Host discovery uses a short-lived Redis cache for ranked database rows, then
  overlays Redis heartbeat freshness before returning host availability.
- Host presence supports `online`, `offline`, `busy`, and `lastSeenAtIso`.
  Expired heartbeat keys make otherwise-online hosts appear `offline` while
  Redis is reachable.
- Call session start stores ephemeral signaling-room participant records and
  marks the host `busy`. Call completion clears busy presence back to `online`
  and invalidates the discovery cache.
- Worker outbox polling uses a Redis lock only to reduce duplicate polling
  bursts. PostgreSQL `SKIP LOCKED` outbox claiming remains the correctness
  mechanism.
- Worker processing of host self-introduction, daily status, and tag-change
  events invalidates host discovery cache groups.

## Redis Restart or Flush

Redis loss cannot lose money, call, application, report, payout, media, admin,
or provider-callback truth. After a Redis restart:

- idempotency replay falls back to `idempotency_records`;
- presence becomes unknown and discovery falls back to PostgreSQL if Redis is
  unavailable;
- if Redis is available but a host heartbeat expired, that host is not presented
  as callable;
- rate limits and OTP throttles restart their windows;
- cached host discovery rows are repopulated from PostgreSQL;
- worker duplicate-suppression locks disappear, but PostgreSQL outbox claiming
  still prevents correctness regressions.

## Tests

`backend/packages/backend-runtime/src/redis-ephemeral.test.ts` covers:

- environment-prefixed versioned keys and inventory ownership;
- heartbeat expiry;
- OTP throttle counters without raw phone numbers in keys;
- cache max-staleness rejection and group invalidation;
- degradable lock behavior.

`backend/apps/api/src/app/server.test.ts` verifies that Redis idempotency
acceleration can be flushed while durable PostgreSQL/memory idempotency replay
still works.

`backend/apps/worker/src/app/worker.test.ts` verifies worker cache invalidation
for discovery-related outbox events.
